The contract

Money is an object.
Errors have a code.

  • amount is a decimal string; minorUnits is the integer a payment processor wants
  • Branch on error.code, never the message. Codes are contract and will not change inside v1
  • A failed cart change still returns the cart, so the UI can re‑render without a second request
every amount, everywhere
{ "amount": "24.99", "minorUnits": 2499,
  "currency": "USD", "formatted": "$24.99" }

24.99 is not an IEEE 754 double, so it never travels as a JSON number.

Payment

Payment that
works headlessly

Any Commerce gateway, off-site ones included. Their redirect comes back as JSON, not a 302 your fetch can’t follow.

  • Return URLs are checked against an allow-list, not a Twig hash
  • The list starts empty, so nothing redirects until you allow it
  • Honour method: GET navigates, POST submits data as a form
